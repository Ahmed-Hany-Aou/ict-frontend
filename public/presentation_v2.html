How Do Humans and Computers Make Decisions?

Sequential Flow: A computer runs commands blindly line-by-line.
Conditional Flow: Gives the computer a "brain" to test live data and choose different paths!
🧠 Human Decision Making

Your senses receive input ➔ your brain evaluates it ➔ you take action:
"IF traffic light is RED ➔ press car brake. ELSE ➔ continue driving."

💻 Computer Decision Making

The program receives variables ➔ tests a condition (True / False) ➔ executes the matching block:
if light == 'RED': stop_car() else: drive()

🚇 Cairo Metro Turnstile

Checks card balance: if credit is sufficient, opens gate. Otherwise, rejects.

if balance >= 10: open_gate()
📱 Fawry / Mobile Cash

Validates wallet funds before approving a bill payment or transfer.

if wallet >= bill: pay_bill()
🚗 Highway Speed Radar

Measures car speed: if speed exceeds 120 km/h, logs an automatic fine.

if speed > 120: log_fine()
The Golden Rule: Input Data ➔ Evaluate Condition (True / False) ➔ Execute Action Page 2
⚙️ The Decision Engine 03 / 11

Anatomy of a Condition: Asking Questions in Code

A Condition is simply a Yes/No question that answers strictly True or False (Boolean value).
Operator Question it Asks Example Expression Evaluation Result
== Are both sides equal? score == 100 True (if score is 100)
!= Are both sides different (not equal)? user != 'admin' True (if regular user)
> and >= Is it greater than (or equal)? marks >= 50 True (Pass Egyptian mark)
< and <= Is it less than (or equal)? balance <= 0 False (if wallet has money)
💡 Key Conceptual Difference: Single = is for assigning a value (x = 5), while Double == is for asking a comparison question (x == 5)!
Logic Rule: A condition has only two possible outcomes: True or False Page 3
🔀 1-Way Selection 04 / 11

1-Way Branching: The "if" Statement

The Concept: Execute an action ONLY IF the condition is met (True). If not met (False), the computer completely ignores it and continues normal flow.
📊 Standard ISO Flowchart
fever_check.py Python
# Screening patient body temp temp = 38.8 if temp > 37.5: print("⚠️ Warning: High fever!") print("Check completed.")
💻 Terminal Output
⚠️ Warning: High fever! Check completed.
Two Syntax Rules: 1. Colon (:) at end of if line | 2. 4-space indentation for the block Page 4
🔀 2-Way Selection 05 / 11

2-Way Branching: The "if...else" Choice

Mutual Exclusivity: The computer faces a fork in the road with two opposite paths. It runs Path A if the condition is True, or runs Path B automatically if False. Exactly ONE path will run!
📊 Driving License Eligibility Flow
license.py Python
age = 17 if age >= 18: print("✅ Approved: Eligible for license.") else: print("❌ Rejected: Underage applicant.")
💻 Terminal Output
❌ Rejected: Underage applicant.
Concept Rule: 'else' takes NO condition because it represents the automatic fallback for all other cases Page 5
🔀 Multi-Way Ladder 06 / 11

Multi-Way Decision: The "if...elif...else" Ladder

First Match Wins: The computer tests conditions sequentially from top to bottom. As soon as one condition is True, it executes that block and immediately exits the entire ladder!
📊 High School Grade Evaluation Flow
grades.py Python
score = 88.5 if score >= 85: print("Excellent (امتياز) 🌟") elif score >= 75: print("Very Good") else: print("Pass / Retake")
💻 Terminal Output
Excellent (امتياز) 🌟
Order Matters: Always place strictest / highest conditions first to avoid skipping high scores Page 6
🔗 Combining Conditions 07 / 11

Logical Operators & The Complete Truth Table (and, or, not)

In real life, decisions often require multiple conditions to be met at the same time (e.g. High GPA AND Clean Record).
Operator Expression Result Intuitive Reason
and True and True True ✅ Both sides are True
and True and False False ❌ One side failed
or True or False True ✅ One True is enough!
or False or False False ❌ Both sides failed
not not True False ❌ Inverts True to False
scholarship.py Python
# University Scholarship Criteria gpa = 3.8 has_violations = False # Both criteria required (and) if gpa >= 3.7 and not has_violations: print("🎉 100% Scholarship Awarded!")
💻 Terminal Output
🎉 100% Scholarship Awarded!
Summary: 'and' requires ALL True | 'or' requires ANY True | 'not' flips the result Page 7
🛠️ Pro Debugging 08 / 11

Top 3 Student Pitfalls to Avoid

Mastering these 3 pitfalls builds strong diagnostic and problem-solving skills in software engineering:
❌ 1. Single '=' inside if

Using = instead of == causes a SyntaxError because it assigns rather than compares.

❌ if x = 10:
✅ if x == 10:
❌ 2. Wrong elif Order

Placing a broad check first (like >= 50 before >= 85) intercepts all cases and hides top scores!

❌ if score >= 50 (First!)
✅ if score >= 85 (First!)
❌ 3. Missing Colon or Indent

Forgetting the colon (:) or failing to indent causes IndentationError.

❌ if score > 50
✅ if score > 50:
Teacher Tip: Always encourage students to dry-run logic on paper before running code on computer Page 8

💼 Real-World Engineering 10 / 11

Case Study: Smart Checkout & Promo Logic (Fawry)

Scenario: A customer buys goods worth 650 EGP. The system grants Free Delivery if the cart is >= 500 EGP AND the promo code matches 'EGYPT2026'.
1️⃣ Input Data
cart_total = 650 EGP
promo = "EGYPT2026"
2️⃣ Compound Condition (Logic)
cart >= 500 (True) AND promo match (True)
➔ Overall: Free Delivery! (Saved 50 EGP)
fawry_checkout.py Python
cart = 650 promo = "EGYPT2026" shipping = 50 if cart >= 500 and promo == "EGYPT2026": shipping = 0 print("🎉 Free Delivery Applied!") print(f"Total Due: {cart + shipping} EGP")
💻 Terminal Output
🎉 Free Delivery Applied! Total Due: 650 EGP
